## Types of arguments
Python handles arguments in a few different ways depending on how you write them:

### Positional Arguments: Assigned based on the exact order you type them.
```python
# If defined as: def setup(pitch, speed)
setup(-40, 20)  # -40 goes to pitch, 20 goes to speed
```

### Keyword Arguments: Assigned by explicitly naming the parameter. Order does not matter here.

```python
setup(speed=20, pitch=-40) # Highly readable and explicit
```
- Default Arguments: Values that take over automatically if you leave them blank when calling the function.

```python
def greet(name, language="en-US"): # "en-US" is the default
```

### Arbitrary Positional Arguments (`*args`)

When you do not know how many positional inputs a user might pass, use a single asterisk (`*`) before a parameter name. Python packs all extra values into a tuple.

```
def sum_numbers(*args):
    return sum(args)

print(sum_numbers(1, 2, 3, 4)) # Output: 10
```

### Arbitrary Keyword Arguments (`**kwargs`)

When you want to accept an unpredictable number of named arguments, use a double asterisk (`**`). Python packs these inputs into a dictionary where the keys are the parameter names.
```
def show_profile(**kwargs):
    for key, value in kwargs.items():
        print(f"{key}: {value}")

show_profile(username="dev_girl", role="admin")
```

## Return Value & Side effect

A return value is ==the final data outcome that a function hands back to the line of code that called it==. 

When a function finishes its calculations, the `return` keyword stops execution and sends that specific piece of data out of the function.

Crucial Difference: Return vs. Print

Many beginners confuse returning data with printing data. 

- `print()`: Simply displays characters on your screen. The computer cannot use that text for any future calculations. It is a visual side effect.
- `return`: Hands the data back to your code. The computer can store it in a variable, pass it to another function, or modify it later. 
---


a side effect ==occurs when a function modifies some state outside of its own local environment, or interacts with the outside world, besides just returning a value==.

If a function does anything other than take an input, calculate something, and return an output, that extra action is a side effect.

#### Common Examples of Side Effects

Your audio greeting code is actually a perfect example of a side effect!

- Interacting with Hardware/OS: Running `spd-say` to play audio through your speakers.
- Modifying Global Variables: Changing a variable that exists outside the function.
- Printing Text: Writing output to the terminal screen via `print()`.
- File I/O: Saving, reading, or deleting a file on your hard drive.
- Network Calls: Fetching data from the internet or sending an API request.
